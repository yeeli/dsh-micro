# DSH小键盘 · dsh-micro

把 **DSH Micro**（与 Codex Micro 同款协议）蓝牙 HID 小键盘接进 **DeepSeek Harness** 的插件。

六颗智能体键对应侧边栏里的会话，用键盘灯光显示每个会话的状态；七路命令（ACT06–ACT12）负责语音、发送、批准/拒绝、归档等常用操作；摇杆与旋钮可以按你的习惯重新分配。所有配置都在 DSH 设置页的「DSH小键盘」分区里完成。

> **当前版本**：0.1.1 ｜ 宿主 + 客户端双端插件 ｜ 在 DSH `0.2.1-rc.2`、macOS 上开发与验证

```text
DSH Micro ── BLE HID（厂商自定义类）──▶ 宿主插件 lib/index.js
   ▲                                    （node-hid · 输入解析 · 灯态）
   └──────── 灯光 / 状态查询 RPC ────────┘
                                          │ /micro/state
                                          │ WebSocket 推送；失败退回 HTTP 轮询
                                          ▼
                                客户端插件 lib/client.js
                                （会话映射 · 按键分派 · 设置页）
```

## 功能一览

- **智能体键（AG00–AG05）**：六个物理键分别对应侧边栏里可见的会话，键下 RGB 灯显示运行中 / 空闲 / 成功 / 失败等状态。映射方式支持「最近的聊天」「已置顶聊天」「优先聊天」「自定义分配」。
- **命令键（ACT06–ACT12）**：出厂为「模式 / 归档 / 拒绝 / 批准 / 按住说话 / 按住说话 / 发送」，每颗键都可以在设置页里改派成任意已接线功能（分叉、终端、新建对话、上传、压缩上下文、目标命令、打开设置……）。
- **按住说话**：语音键按下开始转写、松开结束。检测到官方语音输入 Bundle 时自动让位并驱动官方麦克风，否则回退到浏览器 Web Speech，结果写回输入框。
- **摇杆**：出厂四方向为「上=切换规划模式、右=重做、下=切换侧边栏、左=撤销」，可逐方向改派；推杆时屏幕顶部有实时方向 / 结果提示卡。
- **旋钮**：支持「输入区导航」「仅推理」「对话滚动」「自定义分配」四种模式；按下确认 / 激活，**任何模式下长按都打开本插件设置页**。
- **灯光**：亮度调节、空闲自动调暗、退出 / 卸载时全灭；批准弹窗时当前会话键转琥珀黄，旋钮或「+」招来的弹窗转玫粉。
- **设置页**：连接状态、电量、重新连接、移除键盘、输入监控授权检测、键盘布局可视化、逐键改派、摇杆 / 旋钮映射、独立麦克风键开关、重置布局。
- **首次连接引导**：设备第一次连上时弹出三步说明（欢迎、智能体键图例、命令键），看过只记一次；「重置布局」会清掉记录，下次设备连上时重新出现。
- **侧边栏入口**：设置齿轮旁多一颗小键盘图标，点击直接落到本插件分区；断开时图标带红点，并把 DSH 原来的连接提示改到气泡里显示。
- **稳定的本地链路**：宿主用 `node-hid` 读设备，浏览器通过 WebSocket 接收状态推送；宿主没带 `ws` 时自动退回 120 ms HTTP 轮询。设备掉线后每 30 秒自动重连。

## 硬件与兼容性

本插件面向 **DSH Micro**（与 Codex Micro 同款）的厂商自定义 HID 设备：

| 项目 | 值 |
| --- | --- |
| 设备识别 | `product` 含 `DSH Micro`，`manufacturer` 为 `OMKB LAB` |
| VID:PID | `0x303A:0x8361`（优先按它精确匹配） |
| Report Map | Usage Page `0xFF00`，Report ID `6` |
| 帧格式 | 63 字节：`[channel, len, payload…]`，JSON 行以 `\n` 结尾，可跨帧 |
| 上报示例 | `{"method":"v.oai.hid","params":{"k":"AG00","act":1,"ag":0}}` |
| 灯光协议 | `v.oai.rgbcfg` / `v.oai.thstatus`（Codex Micro 兼容） |
| 电量 | `device.status` 的 `battery` / `is_charging`（不会主动定时推送，需要时向设备查询） |

> ⚠️ 标准 BLE 键盘会被操作系统独占，`node-hid` 读不到；必须使用厂商自定义类（Usage Page `0xFF00`）的固件。设备名 / VID:PID 可以用环境变量覆盖，见[开发与构建](#开发与构建)的环境变量表。

**平台**

- **macOS**：主要开发与验证平台。需要在「系统设置 → 隐私与安全性 → **输入监控**」里勾选运行 DSH 的终端 / 应用，插件设置页会显示授权状态并提供跳转。
- **Windows / Linux**：代码基于 `node-hid`，理论上可用，但本项目未做真机验证。

**软件**

- DSH `0.1.7-rc.2` 及以上（设置命名空间使用该版本起的 loader `Config` 契约），当前在 `0.2.1-rc.2` 上验证。
- 构建需要 Node.js（本项目在 Node 26 上构建；需支持 ESM 顶层 `await`）与 npm。

## 安装

插件以 DSH 组合包（bundle）形式提供，仓库里已经提交了构建产物 `lib/`，因此从 GitHub 安装不需要本地构建。宿主依赖 `node-hid`，首次安装会下载或编译原生模块。

### 从 GitHub 安装

```bash
dsh plugin --profile <profile> add github:yeeli/dsh-micro
```

例如：

```bash
dsh plugin --profile web add github:yeeli/dsh-micro
```

然后在 DSH 的**设置 → 插件管理**里启用 `dsh-micro` 这个组合包，重启 DSH。

> DSH Desktop 的 `desktop` profile 由应用自己持有，命令行会拒绝直接管理；请在桌面端的插件管理界面里安装 / 启用。

### 本地开发安装

```bash
git clone https://github.com/yeeli/dsh-micro.git
cd dsh-micro
npm install
npm run build

dsh plugin --profile <profile> add link:"$PWD"
```

同样需要在插件管理里启用 `dsh-micro`，然后重启 DSH。之后修改源码时运行 `npm run watch` 自动重建；客户端插件会随页面刷新生效。

### 首次使用

1. 在系统蓝牙设置里配对 DSH Micro。
2. 启用插件并重启 DSH，确认设置里出现「DSH小键盘」分区。
3. 设备第一次连上时会弹出三步引导；之后可以点侧边栏齿轮旁的小键盘图标，或**长按旋钮**再次打开设置页。
4. macOS 用户请在设置页的「输入监控」里完成授权（点「打开系统设置」→ 勾选终端 / DSH → 回来点「重新检测」）。

## 快速开始

设备上的物理布局大致是：

- 6 颗**智能体键**（AG00–AG05）
- 7 路**命令键位**（ACT06–ACT09、底部宽 Mic 键的两个开关 ACT10 / ACT11、ACT12）
- 1 个**摇杆**、1 个**旋钮**

默认情况下：

- 智能体键按「最近的聊天」映射侧边栏前六个可见会话；按下打开对应会话。
- 命令键依次是：模式、归档、拒绝、批准、语音（按住；底部宽 Mic 键的两个开关）、发送。
- 摇杆：上=规划模式、右=重做、下=侧边栏、左=撤销。
- 旋钮：输入区导航；长按打开本插件设置页。

打开本插件设置页的三种方式：

1. 侧边栏「设置」齿轮旁边的小键盘图标；
2. **长按旋钮**（任何旋钮模式下都生效）；
3. 把某颗命令键改派成「打开键盘设置页」。

## 按键与手势

### 智能体键（AG00–AG05）

六颗键映射到侧边栏里**可见**的顶层会话（子代理、已归档、空白会话不算），并按下表点亮键下 RGB 灯。

**映射模式**（设置页「智能体键」）：

| 模式 | 行为 |
| --- | --- |
| 最近的聊天（默认） | 按侧边栏「最新在前」取前六个可见会话 |
| 已置顶聊天 | 优先映射置顶会话，其余按最近顺序补齐 |
| 优先聊天 | 运行中的会话排前，同档再按最近排序 |
| 自定义分配 | 六个槽位逐一指定会话；未分配 / 已失效的槽位留空、不亮灯 |

按下智能体键会打开对应会话；会话已经不存在或已被归档时，槽位保持空。

### 命令键（ACT06–ACT12）

| 键码 | 出厂功能 | 说明 |
| --- | --- | --- |
| `ACT06` | 模式 | 在 Agent 预设之间循环切换 |
| `ACT07` | 归档 | 归档当前会话 |
| `ACT08` | 拒绝 | 拒绝 / 跳过当前待确认的审批或选项 |
| `ACT09` | 批准 | 批准 / 下一步当前待确认的审批或选项 |
| `ACT10` | 语音 | **按住说话**，松开结束（合并态下与 ACT11 共用一颗宽键） |
| `ACT11` | 语音 | 合并态同 ACT10；打开「独立麦克风键」后默认未指派 |
| `ACT12` | 发送 | 发送当前输入框内容 |

**改派按键**：设置页「布局」里点任意命令键（或在「编辑按键」弹窗里），从功能列表里选一颗键帽。可选功能包括但不限于：焦点前后移动、上下滚动、滚动到底部、语音、发送、批准、拒绝、归档、分叉、切换推理、增强 / 减弱推理强度、切换 Agent 模式、打开终端、清空输入框、删除一个字、新建对话、上传文件、压缩上下文、在输入框添加目标命令、打开项目文件夹、打开插件管理、打开键盘设置、打开通用设置。

> 键帽即功能：界面上显示的图标就是按下后执行的动作，不存在「显示 SEND、按下却还在录音」的分裂状态。老配置里的键码值继续兼容。

**独立麦克风键**：底部宽 Mic 键下面实际有两个开关（ACT10 / ACT11）。关闭该选项（默认）时它们当一颗宽键用，读写都以 ACT10 为准；打开后拆成两颗键，左键出厂仍是麦克风，右键默认未指派，适合自己改成别的功能。

**按住型动作**：语音是唯一「按下开始、松开结束」的动作；其余命令键都是按下即完成。设备会同时上报按下与松开，长按旋钮的判定也在宿主侧完成。

### 旋钮

| 模式 | 旋转 | 按下 |
| --- | --- | --- |
| 输入区导航（默认） | 在编辑器控件与选项之间移动高亮（跳过文本输入框和语音控件） | 激活当前高亮项 |
| 仅推理 | 打开推理强度菜单，把高亮环移到上一档 / 下一档（转动不提交） | 确认环停的档位；环就在当前档时只收起菜单 |
| 对话滚动 | 滚动当前会话的消息列表 | 回到底部 |
| 自定义分配 | 顺时针 / 逆时针分别执行指定动作 | 执行指定动作 |

- **长按旋钮**：任何模式下都打开「DSH小键盘」设置页。
- 自定义分配的候选与命令键共用同一张功能总表，设置页里选得到的功能就是按下会执行的功能。
- 旋钮按下时如果招来弹窗，当前会话的智能体键会转成玫粉色，弹窗关闭后恢复。

### 摇杆

摇杆按角度归一化为四个方向（右 / 下 / 左 / 上），每进入一个新方向触发一次。出厂映射：

| 方向 | 默认动作 |
| --- | --- |
| 上 | 切换规划模式 |
| 右 | 重做（应用内编辑重做） |
| 下 | 切换侧边栏 |
| 左 | 撤销（应用内编辑撤销） |

四个方向都可以在「模拟摇杆」弹窗里单独改派，也可以设为「不绑定」。推杆时屏幕顶部会显示一张实时提示卡：方向、动作名、执行结果（已触发 / 未绑定 / 未接线 / 未生效），松手后停留约 1.5 秒。

## 灯光

| 颜色 | 含义 | 持续 |
| --- | --- | --- |
| 蓝 | 会话正在运行 | 运行期间 |
| 白 | 会话空闲 | 常亮 |
| 绿 | 刚跑完一轮（成功） | 只有当前会话，约 3 秒后回落 |
| 红 | 该会话运行失败 | 常驻，直到该会话重新运行 |
| 琥珀黄 | 当前有批准 / 拒绝类弹窗，等待你处理 | 弹窗关闭即恢复 |
| 玫粉 | 旋钮或输入框「+」打开的弹窗在场 | 弹窗关闭即恢复 |
| 灭 | 该槽位没有分配会话 | — |

- **亮度**：0–1 可调，实时写回设备。
- **自动调暗**：所有会话空闲达到设定时长后关灯（可选关闭 / 30 秒 / 1 分钟 / 2 分钟 / 5 分钟）；按任意键或会话开始运行会重新点亮。
- **弹窗提醒色优先于失败红灯**：弹窗只是临时覆盖，关闭后红灯原样回来，不需要谁去补一笔。
- **退出即灭灯**：插件卸载、Ctrl+C / SIGTERM 退出时都会把两组灯全部按灭；普通掉线重连**不会**灭灯，避免重连后黑一片。

## 语音输入

语音键是**按住说话**：按下开始、松开结束。

插件支持两条语音链路，按以下优先级选择：

1. **官方语音输入 Bundle**（`@deepseek-ai/dsh-experimental-voice-input-bundle`）
   检测到官方的麦克风 / 录音栏时，本插件自己的麦克风按钮**让位**，语音键改为点击官方的开始 / 停止按钮，转写与插入由官方完成。这样输入区不会同时出现两个麦克风。
2. **浏览器 Web Speech**（`SpeechRecognition` / `webkitSpeechRecognition`）
   官方 Bundle 不可用时回退到浏览器识别，流式结果由插件写回输入框草稿。

识别失败后，官方会把录音栏停在 `feedback` 状态，错误信息挂在那条栏上。此时再按语音键会**先关掉错误栏、等官方麦克风回来再重新开始**（0.1.1 修复）；松手则会取消这次重开，不会出现「松手之后自己开始录音」。

> 输入框上的麦克风按钮也是同一套控制器：点按是开始 / 停止切换。官方 Bundle 在场时该按钮隐藏。

## 设置页

DSH 设置 →「DSH小键盘」分区包含：

| 区块 | 内容 |
| --- | --- |
| 连接 | 已连接 / 连接未成功、电量与充电状态、重新连接、移除键盘 |
| 输入监控（仅 macOS） | 系统授权状态、打开系统设置、重新检测 |
| 亮度 | 0–1 滑杆，写回设备 |
| 自动调暗 | 关闭 / 30 秒 / 1 分钟 / 2 分钟 / 5 分钟 |
| 布局 | 与真机同构的键盘图：按键 / 旋钮 / 摇杆实时演示（此页打开时硬件只演示、不触发功能），可逐键改派、重置布局 |
| 智能体键 | 映射模式、自定义分配的槽位下拉 |
| 旋钮 | 模式选择，以及自定义分配的顺时针 / 逆时针 / 点击动作 |
| 独立麦克风键 | 把底部宽 Mic 键拆成两个独立开关 |
| 第三方插件 | 依赖清单非空时显示；清单为空则整卡隐藏 |

**偏好字段与默认值**（持久化在 DSH 设置命名空间 `dsh-micro` 下）：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `brightness` | `0.9` | 灯光亮度 0–1 |
| `autoDim` | `0` | 空闲自动调暗秒数，0 = 关闭 |
| `actLabels` | `{}` | 命令键覆盖：键码 → 键帽 id；未覆盖的走出厂指派 |
| `joystick` | `{}` | 摇杆四方向映射；缺失的方向走出厂默认 |
| `agentKey` | `"recent"` | `recent` / `pinned` / `priority` / `custom` |
| `agentAssign` | `{}` | 自定义分配：槽位 0–5 → 会话 id |
| `knob` | `"navigate"` | `navigate` / `reasoning` / `scroll` / `custom` |
| `knobCustom` | `{}` | 旋钮自定义：`cw` / `ccw` / `click` → 动作名 |
| `micKey` | `false` | 是否启用独立麦克风键 |
| `guideSeen` | `false` | 首次连接引导是否看过；重置布局会清掉 |
| `removed` | `false` | 生命周期标记，不在界面上显示；设备重新连上自动清除 |

> 出厂默认值的唯一真源是 `src/client/config/default.js`；宿主 schema 在 `src/core/settings.js`，两边逐字段对齐（构建产物分属两个 bundle，无法共享模块）。

**移除键盘**：清空全部偏好并标记 `removed`，界面收起；设备重新连上后自动恢复并重新弹出首次连接引导。

## 提示、诊断与日志

**界面提示**

- 命令键（ACT06–ACT12）按下了但当前页面做不了时，屏幕顶部会提示原因，例如「先打开一个会话，再按这颗键」「当前没有待确认的弹窗」「这次弹窗要选选项：转旋钮选、按旋钮勾」。
- 侧边栏小键盘图标在设备断开时带红点；齿轮那一行原本的连接提示会改成气泡展示（自动重连中 / 连接异常 / 连接成功）。

**浏览器控制台**

```js
__dshMicro                             // 插件共享命名空间
__dshMicro.services.voice.diagnose()   // 语音链路诊断：ready / phase / active / leftover / route
__dshMicro.actions.list()              // 功能总表
__dshMicro.actions.keycaps()           // 可当键帽的功能
__dshMicro.knobTools                   // 推理等级、滚动容器、焦点候选等纯函数
__dshMicro.undoTools                   // 撤销 / 重做的起手式、选择器与真实返回值
__dshMicro.noticeTools                 // 顶部提示的原因表
__dshMicro.footAction                  // 侧边栏入口的定位 / 提示诊断
```

**HTTP / WebSocket 接口**（DSH 本地 webserver，共 8 条 `/micro/*`；`/micro/state` 同时承载 GET 与 WebSocket）：

| 路径 | 方法 | 用途 |
| --- | --- | --- |
| `/micro/state` | `GET` | 状态快照（诊断 / 设置页） |
| `/micro/state` | `Upgrade` | WebSocket 状态推送（客户端常态通道） |
| `/micro/config` | `POST` | 写回亮度 / 自动调暗 |
| `/micro/status` | `POST` | 主动向设备查询一次电量 / 充电状态 |
| `/micro/reconnect` | `POST` | 关闭句柄后重新打开设备 |
| `/micro/agents` | `POST` | 上报灯态（槽位、当前会话、颜色、弹窗态） |
| `/micro/archive` | `POST` | 归档当前会话 |
| `/micro/monitor` | `GET` / `POST` | 读取 macOS 输入监控 / 辅助功能授权 |
| `/micro/open-privacy` | `POST` | 打开系统设置的隐私面板 |

**日志**

- 开发版：日志打到终端。
- 正式版：只写 `$DSH_HOME/logs/dsh-micro.log`（默认 `~/.dsh/logs/dsh-micro.log`），超过 5 MB 时轮转到 `.1`。
- 客户端正式版会去掉所有 `console` 调用；开发版保留日志便于排查。
- 退出时会把两组灯全灭（`dispose` 与进程级退出两条路径）。

## 工作原理与代码结构

**分工**

- **宿主侧**（Node，`lib/index.js`）：持有 HID 句柄，解析输入，维护灯态状态机，注册 `/micro/*` 路由与状态推送，声明设置 schema，处理进程退出安全网。
- **客户端侧**（浏览器，`lib/client.js`）：把会话映射成六个槽位，分派按键 / 摇杆 / 旋钮，探测弹窗与输入监控，渲染设置页与引导，把偏好通过 DSH 设置表单落盘。

**关键设计**

- 每个输入源（旋钮、旋钮按下、长按、摇杆、按键）都有自己的**累加计数器**，浏览器据此归属事件，不靠状态字段猜事件类型。
- 浏览器决定「哪个会话占哪颗键、平时什么颜色」，宿主决定「上一轮跑成了什么」（失败红 / 成功绿），只有宿主写 HID。
- 宿主与客户端分别打包，**不能互相 import**；线格式常量（按键边沿、槽位状态码、电量解析）住在 `src/core/protocol.js`，两侧靠自检断言保持一致。
- `lib/` 是构建产物，**不要手改**；所有改动都在 `src/` 里，然后执行构建。

**目录**

```text
src/
├── core/                  宿主侧
│   ├── index.js           插件入口：总线订阅、设置 schema、生命周期

│   ├── transport.js       node-hid 打开 / 分帧 / 重连 / 退出安全网
│   ├── protocol.js        线格式契约：按键边沿、状态码、电量解析
```

## 开发与构建

```bash
npm install
npm run build        # 开发版：core + client，构建后跑冒烟
npm run watch        # 监听源码自动重建
npm run build:prod   # 正式版：客户端去掉 console，宿主日志只写文件
npm run smoke        # 只跑构建后冒烟
```

- 构建前会先做全量语法检查（`src/check_code.js`），不通过就不写 `lib/`。
- 构建后冒烟会跑几套核心自检；**断言不符只警告，崩溃才阻断构建**。
- 本项目**只有 npm**，没有 pnpm。
- 自检套件 `test/` 按项目约定不纳入版本库；本机保留该目录时可运行 `npm run verify`（25 套），仓库克隆默认没有这些脚本。

**发布流程**：在 `main` 分支上执行 `npm run build:prod` 生成正式版 `lib/`，提交产物并打 `vX.Y.Z` 标签；`develop` 分支保留开发版产物。

**环境变量**

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DSH_HID_VID` | `0x303A` | 设备 VID（十六进制） |
| `DSH_HID_PID` | `0x8361` | 设备 PID（十六进制） |
| `DSH_HID_NAME` | `DSH Micro` | 名称兜底匹配（小写比较，包含即可） |

## 故障排查

| 现象 | 先检查 |
| --- | --- |
| 按键没反应、灯不亮 | 设置页「连接」是否已连接；macOS 是否授予「输入监控」；是否有键盘重映射 / 安全类工具抢占设备；看日志与 `/micro/state` 的 `open` |
| 设备连不上 / 经常掉线 | 系统蓝牙里是否已配对；关闭其他占用 HID 的工具；插件每 30 秒会自动重连，也可以点「重新连接」 |
| 电量一直显示「—」 | 电量需要主动向设备查询：打开设置页、点「重新连接」或 `POST /micro/status`；确认设备固件会回 `device.status` |
| 设置改了不保存 | 确认只启用了一个 `dsh-micro` 组合包；看日志里的 settings 诊断；确认设置命名空间为 `dsh-micro` |
| 侧边栏找不到设置入口 | 新版 DSH 的设置入口可能变成账号菜单；可直接**长按旋钮**，或把命令键改派为「打开键盘设置页」 |
| 语音键按了没反应 | 先看浏览器控制台是否有语音诊断；识别失败后再按会自动关掉错误栏并重开（0.1.1）；确认官方 Bundle 与 Web Speech 至少有一条可用 |
| 输入区出现两个麦克风 | 官方语音 Bundle 在场时本插件会主动隐藏自己的麦克风；若仍出现两个，检查官方 Bundle 是否刚被启停（探测间隔约 1.2 秒） |
| 关掉 DSH 后键盘还亮 | 正常路径会在卸载 / 退出时灭灯；若是被强杀（`kill -9`），进程没有机会写灯，属于已知限制 |
| 开发时改了代码没生效 | `lib/` 是产物：先 `npm run build`（或开着 `npm run watch`），再刷新页面 |

**查看日志**

```bash
tail -f "${DSH_HOME:-$HOME/.dsh}/logs/dsh-micro.log"
```

**手动看状态**

```bash
curl -s http://127.0.0.1:<DSH 端口>/micro/state | jq .
```

状态快照里包含连接状态、设备名、电量、充电状态、当前按下的键、各输入源计数器以及灯态诊断字段。
